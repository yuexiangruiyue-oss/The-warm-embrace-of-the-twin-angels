## 上下文

《双生天使的拥抱》是一款叙事驱动的视觉小说游戏，具有以下技术特征：

1. **核心体验是叙事**：16 章 × 5 拍的分支叙事，大量对话和选择节点。
2. **轻量系统机制**：4 个核心系统（天使陪伴、选择、Sephirot 进程、存在保护），无实时战斗、无物理模拟、无 3D 渲染。
3. **目标平台**：PC（Windows/macOS/Linux），通过 Steam 发行。
4. **无障碍要求**：全面无障碍等级，需要屏幕阅读器支持、文字大小调整等。
5. **团队规模**：小型独立团队，技术人力有限。
6. **美术资产**：2D 立绘 + 背景 + UI，1920×1080，无 3D 资产。

## 备选方案

### 方案 A：Ren'Py 8.x

**概述**：专为视觉小说设计的开源引擎，基于 Python，使用自定义脚本语言 + Screen Language。

**优势**：
- 视觉小说原生支持：对话、分支、存档、CG 图鉴、历史记录等开箱即用。
- Python 扩展：系统逻辑可用纯 Python 实现，满足 C2-C5 的复杂状态管理需求。
- Steam 集成成熟：社区有完善的 Steamworks 封装方案。
- 无障碍：内置 self-voicing（屏幕阅读）、文字大小调整、高对比度模式。
- 开发效率高：叙事脚本编写快速，迭代快。
- 开源免费：无引擎授权费用。
- 社区资源丰富：大量视觉小说项目和教程。

**劣势**：
- 非通用引擎：仅适合视觉小说类型，未来项目复用性低。
- 性能上限有限：不适合高频图形运算（但本项目不需要）。
- Python 性能：热路径性能不如编译语言（但本项目为 I/O 密集型叙事，非 CPU 密集型）。
- UI 自定义限制：Screen Language 灵活度不如通用 UI 框架，但满足本项目需求。

### 方案 B：Unity（URP 2D）

**概述**：通用游戏引擎，使用 C# 开发，支持 2D/3D。

**优势**：
- 通用性强：未来项目可复用引擎经验。
- 生态丰富：Asset Store、社区、工具链成熟。
- 性能优秀：C# + IL2CPP 编译，性能远超 Python。
- UI Toolkit / uGUI：UI 自定义灵活度极高。

**劣势**：
- 过度工程化：视觉小说需要的 90% 功能（对话、分支、存档）需要自行实现或购买插件。
- 开发效率低：相比 Ren'Py，相同叙事内容需要更多代码。
- 引擎授权费用：虽已取消 Runtime Fee，但仍有 Pro 订阅成本（年收入超阈值时）。
- Steam 集成需自行处理（有 Steamworks.NET 等库，但配置复杂）。
- 无障碍支持需自行实现。
- 团队学习成本：需要 C# 和 Unity 编辑器经验。
- 安装体积大：引擎本身数百 MB。

### 方案 C：Godot 4

**概述**：开源通用游戏引擎，使用 GDScript/C# 开发。

**优势**：
- 开源免费：无任何授权费用。
- 2D 性能优秀：专门优化的 2D 渲染管线。
- 轻量级：引擎本身仅数十 MB。
- GDScript 语法简洁，学习成本低。
- 社区活跃且增长快。

**劣势**：
- 无视觉小说原生支持：对话、分支、存档均需自行实现或使用第三方插件（如 Dialogic）。
- Dialogic 功能有限：无法直接满足本项目的复杂系统需求（C2-C5），需大量扩展。
- Steam 集成不成熟：GodotSteam 存在但文档不如 Ren'Py 社区方案完善。
- 无障碍支持不足：缺乏内置 self-voicing 等功能。
- 社区规模小于 Unity/Ren'Py：视觉小说特定问题参考较少。

## 决策

**选择 Ren'Py 8.x。**

### 决策理由

1. **匹配度最高**：本项目是视觉小说，Ren'Py 是视觉小说引擎。90% 的基础功能（对话、分支、存档、历史、CG 图鉴、设置界面）开箱即用，团队精力可集中于差异化系统（C2-C5）。

2. **Python 扩展满足系统复杂度**：C2-C5 的状态管理、数据驱动 JSON 加载、代价计算等逻辑复杂度，Python 完全胜任。通过 `init python` 块可编写完整的系统类，与 Ren'Py 脚本层无缝集成。

3. **无障碍原生支持**：项目要求"全面"无障碍等级。Ren'Py 内置 self-voicing、文字大小调整、高对比度模式等，是唯一无需大量开发工作即可满足要求的引擎。

4. **开发效率是关键约束**：小团队 + 叙事密集型项目 = 开发效率最重要。Ren'Py 的脚本编写速度远超 Unity/Godot（写一行对话 vs 创建 UI 对象 + 绑定 + 脚本）。

5. **性能风险可控**：本项目无实时战斗、无物理模拟、无 3D 渲染。主要性能开销在 Sprite 切换和着色，Ren'Py 的 `im.MatrixColor` 和 transform 系统足以应对。

6. **成本最低**：开源免费，无授权费用，无 Pro 订阅，安装体积小（~50MB 引擎 + 资产）。

### 拒绝其他方案的理由

- **Unity**：过度工程化，为视觉小说使用 Unity 如同用卡车送信——功能充足但效率极低。无障碍需大量自行开发。
- **Godot**：虽有潜力，但视觉小说生态不成熟。Dialogic 无法满足 C2-C5 复杂度，无障碍支持缺失。选择 Godot 意味着在引擎层面重新发明 Ren'Py 已有的功能。

## 后果

### 正面后果

- 叙事开发效率最大化：文案/策划可直接编辑 `.rpy` 脚本或 JSON 数据。
- 无障碍功能开箱即用，减少 2-3 周开发工时。
- 存档系统零开发成本（Ren'Py 自动序列化 `default` 变量）。
- 社区有大量视觉小说最佳实践参考。
- Python 生态系统可直接使用（JSON、数据处理、校验工具等）。

### 负面后果

- 引擎技能不可复用：未来若做非视觉小说项目，Ren'Py 经验不 transferable。
- 性能天花板较低：若未来需要复杂图形效果（如粒子系统、动态光照），Ren'Py 支持有限。
- Python GIL 限制：多线程场景受限（但本项目为单线程叙事，无影响）。
- 引擎更新风险：Ren'Py 由小团队维护，长期支持存在不确定性（但开源，可自行 fork）。

### 风险缓解

| 风险 | 缓解措施 |
|---|---|
| 性能天花板 | 系统层用 Python 实现；图形热路径用 `im.MatrixColor`/transform；如需更高性能可使用 GDExtension（C++ 扩展） |
| 引擎技能不可复用 | 系统架构设计为引擎无关的数据驱动模式；C2-C5 的逻辑可移植到其他引擎 |
| 引擎更新风险 | 钉定 Ren'Py 8.x 特定版本；核心功能不依赖最新 API；fork 作为后备 |
