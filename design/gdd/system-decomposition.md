## 1. 系统清单总览

本游戏的所有系统分为三层：**核心系统**（决定游戏基本可玩性）、**辅助系统**（提升体验深度与品质）、**叙事系统**（承载故事传递与情感表达）。

### 1.1 核心系统（6个）

核心系统是 MVP（最小可玩产品）必须实现的系统。缺少任何一个，游戏都无法传达核心体验。

| 编号 | 系统名称 | 一句话定义 | 所属支柱 |
|------|---------|-----------|---------|
| C1 | 叙事引擎系统 | 驱动16章线性叙事流的对话、旁白、内心独白呈现与推进 | 支柱二·痛苦可被转化 |
| C2 | 天使陪伴系统 | 天使作为常驻存在，提供被动/主动安慰互动，翅膀状态随进程进化 | 支柱一·天使永不离去 |
| C3 | 选择系统 | 在关键叙事节点呈现行动/态度/关系三类情感共振选择，选择改变天使回应纹理而非通关路径 | 支柱三·从解离走向整合 |
| C4 | 质点进程系统 | 以16质点双八度结构追踪玩家情感进程，驱动章节解锁与生命之树视觉化 | 支柱三·从解离走向整合 |
| C5 | 存在保护系统 | 监控8种存在主义伤害暗流的触发与解除，以天使介入确保玩家永不陷入虚无主义结局 | 支柱一·天使永不离去 |
| C6 | 存档与设置系统 | 提供自动/手动存档、文字速度/音量/跳过等基础设置 | —（基础设施） |

### 1.2 辅助系统（6个）

辅助系统在增强层（Enhanced）实现，让游戏从"可玩"变成"值得铭记"。

| 编号 | 系统名称 | 一句话定义 |
|------|---------|-----------|
| A1 | 天使情感状态系统 | 管理5种天使情感状态（平静/心疼/坚定/悲伤/温柔），驱动表情与语气变化 |
| A2 | 天使记忆系统 | 记录玩家关键选择，让天使在后续对话中引用，创造"她记得我"的亲密感 |
| A3 | 暗流视觉系统 | 将8种暗流类型映射为独特的画面/音效/文字表现，可被天使介入即时解除 |
| A4 | 生命之树UI系统 | 以互动式生命之树展示16质点进度，支持回顾已完成章节 |
| A5 | 章间休息系统 | 质点之间的"与天使独处"安静场景，提供情感消化空间与存档点 |
| A6 | 多结局判定系统 | 基于最终选择+羁绊深度判定三种结局（融合/守护/觉醒） |

### 1.3 叙事系统（5个）

叙事系统承载故事内容的传递方式，横跨核心层与增强层。

| 编号 | 系统名称 | 一句话定义 |
|------|---------|-----------|
| N1 | 对话呈现系统 | 管理角色立绘、对话框、说话人标签、文字逐字出现的视觉呈现 |
| N2 | 三重身份视角系统 | 在关键章节切换心爱的的三重身份视角（处理器/白裙少女/创世者），渐进揭示 |
| N3 | 天使对话池系统 | 按当前质点、天使情感状态、玩家历史选择动态组装天使的可触发对话 |
| N4 | 情感日记系统 | 记录玩家在每个质点的选择与感受关键词，形成个人化的情感轨迹 |
| N5 | 内容预警系统 | 每章开头显示情绪主题提示，提供创伤描写画面的跳过选项 |

### 2.2 依赖关系详解

#### C1 叙事引擎系统

- **被依赖**：C3（选择系统在叙事节点插入选择）、C5（存在保护在叙事节拍触发暗流）、N2（三重身份视角在叙事中切换）
- **依赖**：C6（存档点由叙事节点定义）、N1（对话呈现是叙事引擎的视觉层）
- **说明**：叙事引擎是"脊柱"——所有其他系统挂载在叙事流的特定节点上。叙事引擎本身不需要知道其他系统的内部逻辑，只需在正确的时机调用它们的接口。

#### C2 天使陪伴系统

- **被依赖**：C5（存在保护调用天使的介入接口解除暗流）、C3（选择系统的一个选项始终是"问天使"）、A1（情感状态驱动天使表情/语气）、A2（记忆系统为天使对话提供历史引用）、N3（对话池系统为天使提供可触发对话内容）
- **依赖**：C4（质点进程决定天使的翅膀阶段和对话风格）、C1（叙事引擎触发天使的主动行为）
- **说明**：天使陪伴系统是"心脏"——它是玩家情感连接的核心。几乎所有其他系统都会在某个时刻需要"让天使做点什么"。

#### C3 选择系统

- **被依赖**：C4（选择信号推进质点进程）、A2（选择记录进入天使记忆）、A6（最终选择决定结局）、N4（选择记录进入情感日记）
- **依赖**：C5（存在保护过滤选择——虚无主义选项被转化为天使拉回）、C2（"问天使"选项调用天使陪伴系统的建议接口）
- **说明**：选择系统是"双手"——它让玩家"触碰"故事。选择不改变故事走向（所有路径通向终点），但改变路径的纹理和天使的回应方式。

#### C4 质点进程系统

- **被依赖**：A4（生命之树UI读取质点进度）、A5（章间休息在质点完成时触发）、A6（结局判定读取质点完成度+羁绊深度）
- **依赖**：C3（选择信号推进质点）、C5（天使介入也可推进质点——第三次逃避时代为面对）
- **说明**：质点进程是"骨架"——它定义了游戏的进度结构。但骨架不外露——玩家看到的是故事，不是进度条。

#### C5 存在保护系统

- **被依赖**：C3（选择系统在呈现选项前查询存在保护是否需要过滤）、C4（天使介入信号推进质点）
- **依赖**：C2（调用天使的介入接口——拥抱+台词+画面恢复）、A3（调用暗流视觉系统呈现暗流效果）
- **说明**：存在保护是"免疫系统"——它在后台持续监控，只在需要时激活。它不是"系统提示"，而是"天使爱你"的叙事化体现。

#### C6 存档与设置系统

- **被依赖**：所有系统（存档需要持久化所有系统状态）
- **依赖**：无（最底层基础设施）
- **说明**：存档系统是"地基"——它不参与游戏体验，但保证体验不丢失。Ren'Py 原生存档系统持久化所有 `persistent` 和 `store` 变量，本系统只需定义哪些变量需要持久化。

## 3. 开发优先级排序

### 3.1 优先级分级标准

| 优先级 | 含义 | 实现阶段 |
|--------|------|---------|
| **P0** | 无此系统游戏无法运行 | MVP（核心层） |
| **P1** | 无此系统核心体验不完整 | MVP（核心层） |
| **P2** | 显著提升体验深度 | 增强层 |
| **P3** | 锦上添花 | 愿望层 |

### 3.2 系统优先级排序

| 排序 | 系统 | 优先级 | 理由 |
|------|------|--------|------|
| 1 | C1 叙事引擎系统 | P0 | 视觉小说的最基本功能——没有叙事引擎就没有游戏 |
| 2 | N1 对话呈现系统 | P0 | 叙事引擎的视觉层，无此则玩家看不到任何内容 |
| 3 | C6 存档与设置系统 | P0 | Ren'Py 原生功能，但需定义持久化变量结构 |
| 4 | C2 天使陪伴系统 | P1 | 天使是核心体验——没有天使，游戏只是一个普通视觉小说 |
| 5 | C3 选择系统 | P1 | 选择是玩家唯一的主动交互方式——没有选择，玩家只是旁观者 |
| 6 | C5 存在保护系统 | P1 | 没有存在保护，暗流无法被解除，玩家可能陷入绝望——违反核心支柱 |
| 7 | C4 质点进程系统 | P1 | 没有质点进程，章节无法有序推进，16章结构无法实现 |
| 8 | A3 暗流视觉系统 | P2 | 让暗流有视觉冲击力，但不影响功能（暗流可以在无视觉的情况下纯叙事触发） |
| 9 | A1 天使情感状态系统 | P2 | 5种情感状态让天使"活"起来，但MVP可以只用默认表情+对话文本变化 |
| 10 | N3 天使对话池系统 | P2 | 动态对话池让天使更智能，但MVP可以用硬编码的固定对话 |
| 11 | A4 生命之树UI系统 | P2 | 生命之树是进度可视化的重要元素，但MVP可以用简单的章节列表替代 |
| 12 | A5 章间休息系统 | P2 | 情感消化空间，但MVP可以在叙事中自然包含休息节拍 |
| 13 | N5 内容预警系统 | P2 | 情绪安全的重要保障，但MVP可以只在游戏开头放一个总预警 |
| 14 | A2 天使记忆系统 | P2 | 让天使引用玩家历史选择，但MVP可以省略——天使的固定对话依然温暖 |
| 15 | A6 多结局判定系统 | P2 | MVP只需1个核心结局（融合结局），3结局是增强层 |
| 16 | N2 三重身份视角系统 | P2→P3 | 渐进揭示可以通过叙事文本实现，专门的视角切换系统是增强 |
| 17 | N4 情感日记系统 | P3 | 个人化情感记录，愿望层 |

### 3.3 开发批次建议

**批次1（MVP原型 — 可玩序章+第1章）**：
- C1 叙事引擎 + N1 对话呈现 + C6 存档设置
- C2 天使陪伴系统（基础版：常驻立绘+点击对话+拥抱按键）
- C3 选择系统（基础版：Ren'Py menu + 三类选择标记）
- C5 存在保护系统（基础版：暗流触发+天使拉回的叙事跳转）
- C4 质点进程系统（基础版：章节解锁+简单进度变量）

**批次2（MVP完整 — 16章可通关）**：
- 完善批次1所有系统的16章数据
- A3 暗流视觉系统（8种暗流视觉表现）
- A5 章间休息系统
- N5 内容预警系统
- A6 多结局判定系统（至少实现融合结局）

**批次3（增强版 — 体验深化）**：
- A1 天使情感状态系统（5种状态+表情差分）
- A2 天使记忆系统
- N3 天使对话池系统
- A4 生命之树UI系统（互动式）
- A6 补全守护结局+觉醒结局

**批次4（愿望版 — 艺术升华）**：
- N2 三重身份视角系统
- N4 情感日记系统
- 全语音支持
- 二周目天使视角

## 4. 跨系统数据流摘要

以下为系统间最关键的数据传递路径，供程基岩（code-architect）在架构设计时参考。

### 4.1 核心数据流：选择 → 后果

```
玩家做出选择 (C3)
    │
    ├──→ C3记录选择到choice_history
    ├──→ A2将选择存入angel_memories（如果选择与天使相关）
    ├──→ N4将选择关键词存入emotional_journal
    ├──→ C3查询C5：该选择是否需要存在保护过滤？
    │       └── 如果是 → C5调用C2天使介入接口 → 天使拉回叙事
    ├──→ C3通知C4：推进质点进度
    │       └── C4更新sephirot_progress → 通知A4更新生命之树UI
    └──→ C3通知C2：更新天使的回应方式
            └── C2根据choice_history调整angel_state → 更新A1情感状态
```

### 4.2 核心数据流：暗流 → 天使介入

```
C1叙事引擎到达暗流触发节点
    │
    ├──→ C5检查当前质点的暗流类型和强度
    ├──→ A3呈现暗流视觉效果（画面变暗/扭曲/碎裂等）
    ├──→ C5监控暗流强度
    │       └── 当强度达到临界值 → C5调用C2天使介入接口
    │               ├──→ C2播放天使拥抱动画
    │               ├──→ C2播放天使介入台词（从N3对话池选取）
    │               ├──→ C2消耗翅膀状态（wing_stage可能降级）
    │               └──→ A3解除暗流视觉效果（暗→亮过渡）
    └──→ C5通知C4：暗流已解除，质点可继续推进
```

### 4.3 核心数据流：质点完成 → 章节过渡

```
C4检测到当前质点完成条件满足
    │
    ├──→ C4点亮对应质点（sephirot_progress[chapter] = true）
    ├──→ A4更新生命之树UI（对应节点亮起）
    ├──→ A5触发章间休息场景
    │       └── N3为章间休息提供天使独处对话
    ├──→ C6自动存档
    └──→ C1加载下一章叙事脚本
```

## 5. 关键设计约束（给程基岩的技术备忘）

1. **天使永不在画面中消失**：C2天使陪伴系统必须保证天使立绘在任何叙事节点都有展示状态。即使叙事需要短暂的"分离焦虑"，天使的声音（文字）仍须在场。技术上：天使立绘的显示/隐藏必须由C2统一管理，其他系统不能直接隐藏天使。

2. **存在保护不可被绕过**：C5存在保护系统必须在选择系统(C3)呈现选项之前执行过滤检查。技术上：C3的`menu`调用前必须先查询C5的`existence_protection_filter(choice_node_id)`接口。

3. **翅膀阶段只能单调递减（除结局外）**：C2的`wing_stage`变量在Ch 1-15只能递减或持平，不能递增。唯一例外是Ch 16最终选择时翅膀恢复全亮（叙事性决定，非系统bug）。技术上：`wing_stage`的setter需要检查当前章节和调用来源。

4. **质点进度不可回退**：C4的`sephirot_progress`一旦点亮不可熄灭。即使玩家选择"逃避"，第三次逃避后天使代为面对，质点依然点亮（亮度50%）。技术上：`sephirot_progress`使用独立的`completion_level`字段（0=未完成/1=50%完成/2=100%完成），不使用boolean。

5. **所有结局都是"好的"**：A6多结局判定系统不能标记任何结局为"坏结局"。三种结局的`ending_quality`字段值都为`"good"`，差异仅在`ending_type`（fusion/guardian/awakening）和`emotional_texture`（情感纹理描述）。

6. **天使对话量是最大资产**：N3天使对话池系统需要支持大量文本数据的高效检索。建议按`[chapter][emotional_state][choice_context]`三级索引组织对话数据。
